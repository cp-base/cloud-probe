## v0.3：床なし表示・起点の敵・待機と巡回

2026-11-07。**処理42項目＋UI6項目、失敗0。** 以下のv0.2の記録は以前の版の結果です。

- 起点から約179の追加敵が1体だけ現れること、通常の区画生成では重複しないこと。
- 同じ4戦闘タイプと別に、待機・巡回が共存すること。
- 探知外では待機個体が止まり、巡回個体が前後30の範囲を往復・折り返すこと。一時停止では巡回も止まること。
- 保存・再開で個体の行動、巡回方向と往復の向きが残ること。行動の指定がない旧個体は待機として動くこと。
- 格子床のPlaneMeshがなく、カメラが高さ0にあること。光用のQuadMeshは床と区別すること。
- 従来の探索・戦闘・成長・施設・活動・保存の検査も通過。

[v0.3処理検査ログ](foundation-v03-tests.log)／[v0.3 UI検査ログ](foundation-v03-ui-tests.log)

## v0.2の確認記録

## 処理の検査：36項目、失敗0

`tests/test_session.gd` をGodotのheadless実行で確認しました。
生の出力は [処理検査ログ](foundation-tests.log) です。

| 対象 | 確認した内容 |
|---|---|
| 世界生成 | 同じ種・出撃・区画なら訪問順に依存しない。480四方に最大1対象、一般生成同士150以上。13×13区画で敵4タイプ共存 |
| 初期探索から成長 | 初期状態で実際の生成光へtickで航行→自動回収→燃料切れ帰還→得た資金で航続改修→再出発で新容量 |
| 戦闘 | 砲撃・近接の自動切替、切替時の共通待ち時間、撃破の二重報酬防止、地理的深度で固定された強さ |
| 強化の意味 | 同じ重装敵へ初期性能で敗北、強化後に撃破。敵と能力を注入した比較であり、自然発見による試遊ではない |
| 施設 | 発見→建設→登録→別施設から出発→保存・再開でも建設と出発地点を保持。遠隔改修・二重建設を拒否 |
| 記録・信号 | 地点メモ削除が施設へ影響しない。信号の任意選択と二重回収防止 |
| 交易 | 購入→積載→別施設で売却。同一施設往復では利益なし。満載では課金しない |
| 派遣 | 1枠の重複依頼を拒否、90秒の航行時間で完了、停止中は進まない、報告の二重受領防止 |
| 保存 | 現在地・燃料・待ち時間・飛翔中の攻撃・敵耐久、荷物・メモ・依頼を復元。回収済みの光が再出現しない。保存した攻撃は一度だけ解決 |
| 保存の保護 | 非対応版を拒否し、上書き要求後も元ファイルのSHA-256が一致 |
| 境界 | 座標を9999.8へ注入し、境界10000への移動制限と到達記録を確認。通常の攻略到達ではない |

テストの後半では遠方施設の座標、資金、敵、能力、境界位置を明示的に与えています。
実際のプレイヤー用保存は使わず、`tests/.state/` に検査用の保存を作成しました。

## 実画面の操作確認

実ゲームのウィンドウでボタンとキーを操作しました。最初の通常航行には座標・資金・能力を注入していません。

1. 初期の施設画面を開き、5タブと初期資源、資金不足時の改修・装備表示を確認。
2. 出発し、正面の光と周囲の少ない対象を確認。追加の発光設定はOFF。
3. 自動前進で生成光を1つ回収し、施設初発見・地図表示・旅先の交易施設へアクセス。
4. 補給せず進み、最深約306、回収1、資金8Cで燃料切れ帰還。
5. 画面で4Cを支払って航続Lv.1へ改修。資金4C、容量125、積載4へ更新。
6. 通常終了して再起動。資金4C、容量125、初回の報告、発見施設を復元した準備画面を確認。

## 修正した問題

- 初回読み込み時の型推論エラーを修正。Godotは構文エラーがあってもインポートの終了コードが0だったため、ログのエラー行まで確認しました。
- JSONから復元した投射物の配列は、型付き配列へ `assign` して復元。
- 地図の選択目標より光の案内が優先されていた処理を修正し、UI検査へ追加。
- テスト追加時の予約語との衝突を修正し、最終ログは36項目通過。
- 以前の光の非表示問題への修正（unshadedでALBEDOから色を出す）は引き継ぎ、実画面でも再確認。
